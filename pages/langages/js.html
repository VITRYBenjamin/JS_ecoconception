JavaScript - Éco-conception & Green Coding

PHP Python C/C++ (bientôt) Java Rust (bientôt) Dart JavaScript

JavaScript est le langage dominant côté client, exécuté par 100% des navigateurs web modernes et omniprésent dans les sites, apps et frameworks frontend. Malgré sa flexibilité, son usage massif peut entraîner une forte consommation CPU, mémoire, batterie et des transferts réseau inutiles.


Cette page présente une sélection de bonnes pratiques d'écoconception spécifiques à JavaScript, couvrant le chargement, l'exécution, la mémoire, le réseau et les frameworks, avec des exemples concrets, gains estimés, et anti-patterns courants.

Les 10 Règles d'Éco-conception JavaScript

1 Throttle & Debounce des événements fréquents

Impact ⭐⭐⭐

Les événements comme scroll, resize, ou input peuvent se déclencher des centaines de fois par seconde. Utiliser throttle() ou debounce() réduit drastiquement l'utilisation CPU et prolonge la batterie.

Gain estimé : CPU -30 à -90%, autonomie +20% sur mobile

Mauvais :

window.addEventListener('scroll', () => {
        // Exécuté 100+ fois par seconde
        updateProgressBar();
        });

Bon : 

function throttle(fn, delay) {
        let last = 0;
        return (...args) => {
            const now = Date.now();
            if (now - last >= delay) {
                last = now;
                fn(...args);
            }
        };
        }

        window.addEventListener('scroll', throttle(updateProgressBar, 200), { passive: true });

2 Lazy Loading des modules JavaScript

Impact ⭐⭐⭐

Charger uniquement le code nécessaire au démarrage et différer le reste améliore considérablement le temps de chargement initial.

Gain estimé : -200 à -800 KB transférés, LCP amélioré de 30-50%

Mauvais :

import Chart from 'chart.js';
        import Analytics from './analytics';
        import HeavyEditor from './editor';

        // Tout est chargé dès le début

Bon : 

// Chargement à la demande
        async function showChart(data) {
        const { default: Chart } = await import('chart.js');
        return new Chart(data);
        }

        button.addEventListener('click', async () => {
        const { default: Editor } = await import('./editor');
        new Editor();
        });

3 Import sélectif depuis les bibliothèques

Impact ⭐⭐⭐

Importer uniquement les fonctions nécessaires plutôt que la bibliothèque entière réduit drastiquement le poids du bundle.

Gain estimé : -50 à -500 KB, parsing 2× plus rapide

Mauvais :

import _ from 'lodash';

        const result = _.debounce(fn, 300);
        // Charge 70KB pour une seule fonction !

Bon : 

import debounce from 'lodash/debounce';

        const result = debounce(fn, 300);
        // Seulement 2KB chargés

4 Code Splitting par routes/pages

Impact ⭐⭐

Diviser le code en chunks par route permet de ne charger que le JavaScript nécessaire pour la page actuelle.

Gain estimé : FCP plus rapide, CPU réduit au démarrage

Mauvais :

import HomePage from './pages/Home';
        import AboutPage from './pages/About';
        import DashboardPage from './pages/Dashboard';

        // Toutes les pages sont dans le bundle initial

Bon (React) :

import { lazy, Suspense } from 'react';

        const HomePage = lazy(() => import('./pages/Home'));
        const AboutPage = lazy(() => import('./pages/About'));
        const DashboardPage = lazy(() => import('./pages/Dashboard'));

        function App() {
        return <Suspense fallback={<Loading />}>
            {/* Chaque page se charge à la demande */}
        </Suspense>;
        }

5 requestAnimationFrame au lieu de setInterval

Impact ⭐⭐

Pour les animations, requestAnimationFrame() synchronise avec le rafraîchissement de l'écran et s'arrête quand l'onglet est inactif.

Gain estimé : -20 à -60% rendu inutile, fluidité accrue

Mauvais :

setInterval(() => {
        box.style.left = position++ + 'px';
        }, 16);
        // Continue même si l'onglet est caché

Bon : 

function animate() {
        box.style.left = position++ + 'px';
        requestAnimationFrame(animate);
        }

        requestAnimationFrame(animate);
        // S'arrête automatiquement quand l'onglet est inactif

6 Nettoyage des listeners et timers

Impact ⭐⭐

Les event listeners, timers et observateurs non supprimés créent des fuites mémoire. Toujours les nettoyer lors du démontage.

Gain estimé : -10 à -30% mémoire persistante, prévention des fuites

Mauvais :

function setupWidget() {
        window.addEventListener('resize', handleResize);
        setInterval(updateStatus, 5000);
        // Jamais nettoyé !
        }

Bon : 

function setupWidget() {
        window.addEventListener('resize', handleResize);
        const interval = setInterval(updateStatus, 5000);

        return () => {
            window.removeEventListener('resize', handleResize);
            clearInterval(interval);
        };
        }

        const cleanup = setupWidget();
        // Plus tard : cleanup();

7 Envoyer uniquement les données nécessaires

Impact ⭐

Éviter de transférer des objets JSON avec des champs inutiles. Filtrer côté serveur ou supprimer les propriétés superflues.

Gain estimé : -30 à -90% taille JSON, parsing plus rapide

Mauvais :

// API renvoie tout l'objet user avec 50 champs
        const res = await fetch('/api/users');
        const users = await res.json();
        // On utilise seulement id, name, email

Bon : 

// API ne renvoie que les champs demandés
        const res = await fetch('/api/users?fields=id,name,email');
        const users = await res.json();
        // JSON 80% plus léger

8 Batcher les requêtes API

Impact ⭐⭐

Regrouper plusieurs appels API en une seule requête réduit la latence réseau et économise la batterie (moins de wake-up radio).

Gain estimé : -20 à -70% de requêtes, moins de wake-up radio

Mauvais :

for (const id of productIds) {
        const res = await fetch(`/api/products/${id}`);
        const product = await res.json();
        // 20 produits = 20 requêtes HTTP
        }

Bon : 

// Une seule requête batch
        const ids = productIds.join(',');
        const res = await fetch(`/api/products?ids=${ids}`);
        const products = await res.json();
        // 20 produits = 1 requête HTTP

9 Utiliser des frameworks légers

Impact ⭐⭐⭐

Pour les projets simples, préférer Preact, Svelte, ou Vanilla JS plutôt que React. Pour les projets complexes, optimiser avec SSR/SSG.

Gain estimé : -200 à -800 KB bundle, -30% CPU
Comparaison des tailles :
  • React + ReactDOM : ~140 KB
  • Preact : ~4 KB
  • Svelte : ~2 KB (runtime)
  • Vanilla JS : 0 KB

Exemple Preact :

import { h, render } from 'preact';

        function App() {
        return <div>Hello Preact!</div>;
        }

        render(<App />, document.body);
        // API identique à React, 35× plus léger

10 Mémoïsation des calculs coûteux

Impact ⭐⭐

Utiliser useMemo (React) ou un cache manuel (Map/WeakMap) pour éviter de recalculer les mêmes valeurs.

Gain estimé : UI ×2 à ×5 plus réactive sur les opérations lourdes

Mauvais :

function ProductList({ products }) {
        const sorted = products.sort((a, b) => b.price - a.price);
        // Re-trie à chaque rendu, même si products n'a pas changé
        return <div>...</div>;
        }

Bon (React) :

import { useMemo } from 'react';

        function ProductList({ products }) {
        const sorted = useMemo(() => {
            return products.sort((a, b) => b.price - a.price);
        }, [products]);
        // Ne recalcule que si products change
        return <div>...</div>;
        }

Bonnes pratiques complémentaires

Regrouper les modifications DOM

const frag = document.createDocumentFragment();

for (let i = 0; i < items.length; i++) {
  const li = document.createElement('li');
  li.textContent = items[i];
  frag.appendChild(li);
}
list.appendChild(frag);

Évite les multiples reflows → 1 seule insertion

Délégation d'événements

container.addEventListener('click', (e) => {
  const btn = e.target.closest('button');
  if (!btn) return;
  handleClick(btn);
});

1 seul listener au lieu de N → économie mémoire

Cache des sélecteurs DOM

const statusEl = document.querySelector('#status');

function update(text) {
  statusEl.textContent = text;
}

Évite les querySelector répétés → moins de CPU

WeakMap pour cache DOM

const cache = new WeakMap();

function getMeta(node) {
  if (!cache.has(node)) {
    cache.set(node, {
      created: Date.now()
    });
  }
  return cache.get(node);
}

Prévient les fuites mémoire → GC libère les nœuds

AbortController pour fetch

let ctrl;

async function search(q) {
  if (ctrl) ctrl.abort();
  ctrl = new AbortController();

  const res = await fetch(
    `/search?q=${q}`,
    { signal: ctrl.signal }
  );
  return res.json();
}

Annule les requêtes obsolètes → économie réseau

Web Workers pour calculs lourds

const worker = new Worker('heavy-calc.js');

worker.postMessage(largeData);

worker.onmessage = (e) => {
  displayResults(e.data);
};

Libère le thread principal → UI fluide
