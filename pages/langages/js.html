JavaScript - Éco-conception & Green Coding

PHP Python (bientôt) C/C++ (bientôt) Java (bientôt) Rust (bientôt) JavaScript

JavaScript est le langage dominant côté client, exécuté par 100% des navigateurs web modernes et omniprésent dans les sites, apps et frameworks frontend. Malgré sa flexibilité, son usage massif peut entraîner une forte consommation CPU, mémoire, batterie et des transferts réseau inutiles.


Cette page présente une sélection de bonnes pratiques d'écoconception spécifiques à JavaScript, couvrant le chargement, l'exécution, la mémoire, le réseau et les frameworks, avec des exemples concrets, gains estimés, et anti-patterns courants.

Bonnes pratiques complémentaires (5)

1 Réduire les reflows : regrouper les modifications DOM

Modifier le DOM en boucle déclenche des recalculs de layout coûteux ; regrouper les changements réduit le travail du navigateur.

Mauvais :

for (let i = 0; i < items.length; i++) {
        const li = document.createElement('li');
        li.textContent = items[i];
        list.appendChild(li); // layout potentiel à répétition
        }

Bon :

const frag = document.createDocumentFragment();

        for (let i = 0; i < items.length; i++) {
        const li = document.createElement('li');
        li.textContent = items[i];
        frag.appendChild(li);
        }

        list.appendChild(frag); // 1 insertion, 1 recalcul

2 Préférer la délégation d’événements

Ajouter un listener par élément coûte en mémoire ; un seul listener sur le parent suffit dans la plupart des listes dynamiques.

Mauvais :

buttons.forEach((btn) => {
        btn.addEventListener('click', handleClick);
        });

Bon :

container.addEventListener('click', (e) => {
        const btn = e.target.closest('button[data-action]');
        if (!btn) return;
        handleClick(btn.dataset.action);
        });

3 Mettre en cache les sélecteurs DOM

Refaire querySelector à répétition est inutile ; stocker la référence évite du travail au navigateur.

Mauvais :

function update(text) {
        document.querySelector('#status').textContent = text;
        }

Bon :

const statusEl = document.querySelector('#status');

        function update(text) {
        statusEl.textContent = text;
        }

4 Utiliser WeakMap / WeakSet pour les caches liés au DOM

Un cache classique peut empêcher le GC de libérer des éléments supprimés ; WeakMap évite de retenir des objets “morts”.

Mauvais :

const cache = new Map();

        function getMeta(node) {
        if (!cache.has(node)) {
            cache.set(node, { created: Date.now() });
        }
        return cache.get(node);
        }

Bon :

const cache = new WeakMap();

        function getMeta(node) {
        if (!cache.has(node)) {
            cache.set(node, { created: Date.now() });
        }
        return cache.get(node);
        }

5 Annuler les fetch inutiles avec AbortController

Quand une requête devient obsolète (ex: recherche), l’annuler évite du réseau et des traitements côté client/serveur.

Mauvais :

async function search(q) {
        const res = await fetch(`/search?q=${q}`);
        return res.json(); // anciennes réponses peuvent arriver après
        }

Bon :

let ctrl;

        async function search(q) {
        if (ctrl) ctrl.abort();
        ctrl = new AbortController();

        const res = await fetch(`/search?q=${q}`, { signal: ctrl.signal });
        return res.json();
        }
