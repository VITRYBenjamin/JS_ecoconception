JavaScript - Éco-conception & Green Coding

PHP Python (bientôt) C/C++ (bientôt) Java (bientôt) Rust (bientôt) JavaScript

JavaScript est le langage dominant côté client, exécuté par 100% des navigateurs web modernes et omniprésent dans les sites, apps et frameworks frontend. Malgré sa flexibilité, son usage massif peut entraîner une forte consommation CPU, mémoire, batterie et des transferts réseau inutiles.


Cette page présente une sélection de bonnes pratiques d'écoconception spécifiques à JavaScript, couvrant le chargement, l'exécution, la mémoire, le réseau et les frameworks, avec des exemples concrets, gains estimés, et anti-patterns courants.

# Règle Éco-responsabilité Bonne pratique Gain estimé Impact
1 throttle_events Réduire le CPU & batterie liés aux scroll/input Utiliser throttle() ou debounce() CPU -30 à -90%, autonomie +20% sur mobile ⭐⭐⭐
2 lazy_load_js Réduire JS initialement chargé Lazy loading des modules -200 à -800 KB transférés, LCP amélioré ⭐⭐⭐
3 import_selectif Réduire le poids du bundle Import ciblé (ex: lodash/debounce) -50 à -500 KB, parsing 2× plus rapide ⭐⭐⭐
4 code_splitting Réduire le JS critique initial Split par routes/pages FCP plus rapide, CPU réduit au démarrage ⭐⭐
5 rAF_vs_interval Limiter les frames gaspillées Utiliser requestAnimationFrame() -20 à -60% rendu inutile, fluidité accrue ⭐⭐
6 nettoyage_refs Réduire les fuites mémoire Supprimer listeners et timers orphelins -10 à -30% mémoire persistante ⭐⭐
7 eviter_json_lourd Limiter les données transférées Envoyer JSON léger et pertinent -30 à -90% taille JSON, parsing plus rapide ⭐
8 batched_requests Réduire les requêtes inutiles Batcher ou différer les appels API -20 à -70% de requêtes, moins de wake-up radio ⭐⭐
9 framework_legers Réduire la charge JS côté client Utiliser Preact, Svelte ou Vanilla JS -200 à -800 KB, -30% CPU ⭐⭐⭐
10 memoisation_pure Éviter les recalculs redondants Utiliser useMemo, cache Map/WeakMap UI ×2 à ×5 plus réactive ⭐⭐
